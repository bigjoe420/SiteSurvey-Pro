2. main/display/display.cpp — v6.1 SPI PSRAM DMA fix (boot freeze)
   - io_cfg.flags.psram_dma_direct = 1 in display_init()
   - v6.1 allocates a per-flush internal-RAM bounce buffer when LVGL draw buffers
     live in PSRAM; once WiFi+BLE claimed internal RAM the alloc failed forever
     ("Failed to allocate priv TX buffer" flood, ~120/s) and the panel froze on
     the splash. Direct PSRAM DMA removes the bounce buffer entirely.

3. sdkconfig.defaults (+ regenerated sdkconfig) — BLE observer-only trim
   - ROLE_CENTRAL/PERIPHERAL/BROADCASTER=n, GATT_CLIENT/SERVER=n, SECURITY=n
   - Fixes ble_scan rc=519 (BLE_ERR_MEM_CAPACITY) under WiFi+BLE coexistence
   - GOTCHA: sdkconfig.defaults does NOT override an existing sdkconfig.
     Must delete sdkconfig to force regeneration, else the build silently
     keeps old config (binary size unchanged is the tell: 0x1d79e0 → 0x1c1250).

Binary: 0x1c1250 (~1.77 MB), 12% free. Verified on COM3 via 40 s clean boot capture
(boot_log2_clean.txt): zero SPI/LCD errors, zero BLE errors, BLE scan started per

================================================================================
Critical lessons for next session
================================================================================
1. RMT struct field order matters: rmt_symbol_word_t = {duration0, level0,
   duration1, level1}. Designated initializers must match declaration order.
2. BIT0/BIT1 are macros in esp_bit_defs.h. Never use them as variable names.
3. ESP_RETURN_ON_ERROR requires #include "esp_check.h".
4. Build via: powershell -File tools/idfenv.ps1 idf.py build
5. Flash via: powershell -File tools/idfenv.ps1 idf.py flash -p COM3
   (Git Bash: python idf_run.py build / python idf_run.py -p COM3 flash —
    v6.1 refuses MSYS; idf_run.py strips MSYSTEM and runs export.bat under cmd)
6. power_mgr bl_apply() needs s_initialized=true FIRST — never apply brightness
   before the init flag is set, or the boot backlight silently stays off.
7. On IDF v6.1, PSRAM-resident LVGL draw buffers need
   esp_lcd_panel_io_spi_config_t.flags.psram_dma_direct = 1, or the SPI driver
   malloc's a per-flush internal-RAM bounce buffer that fails once WiFi+BLE
   are up → frozen splash, "Failed to allocate priv TX buffer" flood.
8. Editing sdkconfig.defaults has NO effect while sdkconfig exists. Delete
   sdkconfig (build regenerates it) — unchanged binary size means the config
   change never took.
9. NimBLE observer-only (no central/peripheral/GATT/security) is required for
   WiFi+BLE coexistence on ESP32-C5 v6.1 — full stack hits
   BLE_ERR_MEM_CAPACITY (rc=519).
